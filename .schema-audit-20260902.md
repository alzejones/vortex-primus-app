### 3. Tabela `product_reminder_queue` (nova)
```sql
CREATE TABLE product_reminder_queue (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  trainer_id uuid NOT NULL REFERENCES trainers(id) ON DELETE CASCADE,
  client_id uuid REFERENCES clients(id) ON DELETE CASCADE,
  sale_item_id uuid REFERENCES herbalife_sale_items(id) ON DELETE CASCADE,
  product_name text,
  scheduled_date date,
  message_text text,
  status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'sent', 'dismissed')),
  sent_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_product_reminder_queue_trainer_status 
  ON product_reminder_queue(trainer_id, status);

CREATE INDEX idx_product_reminder_queue_scheduled_date 
  ON product_reminder_queue(scheduled_date) WHERE status = 'pending';
```
**Status:** ✅ Aplicado em produção

## Lições Aprendidas

1. **Sempre criar migration antes de aplicar em produção** (mesmo durante desenvolvimento)
2. **Auditar schema periodicamente** (especialmente após features grandes)
3. **Migration é documentação** (facilita rollback e compreensão futura)
